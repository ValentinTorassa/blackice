# Introduction

blackice is an application firewall for macOS, run from the command line. It sees every new outbound connection, from any app, and treats it by mode:

- `accept-all` lets everything through and logs it.
- `ask` holds a connection that no rule covers until you or an agent answers. No answer in time means it is dropped.
- `block-all` lets through only what your rules allow.

## Ask mode

<FigAsk n={1} />

Rules, the built-in list of macOS services and current approvals are checked first, so only new destinations wait. You answer with `blackice approve` or `blackice deny`, or from the menu bar, with Touch ID. An agent answers through a hook: the daemon runs it and reads its last line, `approve 1h` or `deny`. An approval covers one app and one host, and expires. A deny is remembered for 10 minutes.

## The parts

<FigArchitecture n={2} />

- **Blackice.app**, in `/Applications`, holds the network extension and the `blackice` command, which is also the menu bar app.
- **The extension** sees each new connection, and allows, holds or drops it.
- **The daemon** runs the hooks, as a LaunchAgent for your user. It takes them from the configuration saved with Touch ID, never from a file, and answers with the event's one-time token, which the hook never sees.

## Limits

- Any program running as you can steer a hook: rewrite the event file while the agent reads it, or the rules and sign-in in the agent's home, and so get its own connection approved. An approval still covers only the event's app and host, for at most 24 hours.
- Host and app names come from whoever opens the connection, and they reach the agent's prompt. The only answers taken are `deny` and `approve` with a duration, for the event's app and host.
- A program running as you can stop the daemon. Connections then wait and are dropped at their timeout.
- A tool that connects to an address, such as `curl`, fails on its first try when the answer takes longer than the server waits, and gets through on the retry. Apps that connect by name wait for the answer.
- A `run` hook's program is not checked. A `program` hook starts only when its signature matches, and with SIP off macOS does not check that before it runs.
