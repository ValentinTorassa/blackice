# Introduction

blackice is a headless application firewall for macOS, operated through a CLI. A connection that no rule covers can wait for you, or for an agent behind a hook, to approve or deny it.

<Status />

blackice is a network extension, a small daemon and a CLI. The extension sees every new outbound connection on the Mac, from any app. There are three modes. Accept all lets everything through, block all drops everything that no rule allows, and ask pauses each new connection that no rule or approval covers until it gets an answer.

Answers go through the command line, for example `blackice approve --app com.example.tool --host example.com --for 1h`. You can give them yourself, with Touch ID, or a hook can pass the request to an agent such as fx, which answers with its last line of output, `approve 1h` or `deny`, for the app and host it was asked about. There is no dialog to click.

## Status

0.3.2 is the current release ([changelog](/docs/changelog)). On one Mac, a MacBook Air with macOS 27.0.1:

- In block-all, a binary signed with the project's Team ID and named by no rule was refused, and `curl` with a rule got through.
- In ask mode, fx, run by the hook, approved and denied connections, and in one run decided ten in a row with nobody at the keyboard. Apps that connect by name, such as `nscurl`, wait for the answer. `curl` and other tools that connect to an address fail on the first try and get through on the retry after an approval.
- The fault tests passed for the daemon being down, a hung hook, a burst of 120 connections, a daemon restart and a configuration change while connections wait. The configuration change first failed with an earlier build, and passed with 0.2.1.
- From the published 0.2.1, the uninstall steps of [Install](/docs/install) removed the previous install, and the install script checked the release and installed it into `/Applications`.
- After an upgrade in place, the daemon and the CLI could not reach the new extension until the Mac restarted.
- With 0.3.0 candidates and no blackice or fx on the Mac, the first `start` asked its questions as lists, installed fx and signed it in. fx's test failed with HTTP 403 for a Vercel team with no card on file. With an earlier sign-in, `blackice agent connect fx` turned ask mode on, and fx approved two connections about 5 s after they started.
- An earlier 0.3.0 candidate dropped git over HTTPS, `notarytool` and Apple's other developer tools in ask mode without asking. The 0.3.0 release asks about them, and fx approved git and `notarytool` in about 5 s.
- From the published 0.3.0, one `blackice start` went from its lists to ask mode with fx answering in 1 min 16 s. In the next ten minutes, bursts of connections from a VPN client outran fx, which runs at most 4 at once, and 31 connections were dropped at their deadline.

[Install](/docs/install) has the steps. The phases and open problems are in the repository's [plan](https://github.com/ValentinTorassa/blackice/blob/main/docs/plan.md).

## Why

Agents run on developer machines all day and need to make network decisions without a person at the keyboard. The code that sees every connection on a machine is also a sensitive place for a dependency, so the aim is to keep blackice small and without third-party dependencies.

## Relation to the first proof of concept

The first blackice, now [blackice-poc](https://github.com/ValentinTorassa/blackice-poc) and archived, confines one command and everything it starts, with a fixed policy file, and never asks. This blackice covers the whole machine, and in ask mode it holds a new connection until you or an agent answers. It starts from blackice-poc's macOS app filter: the Network Extension, app identity from code signatures, and the TLS server name reader.
