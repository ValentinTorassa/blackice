# Install

Install blackice 0.3.2 with the install script, Homebrew or the release zip, check it, start it, remove it and roll it back.

<Status />

The release package is `Blackice-0.3.2.zip` plus `Blackice-0.3.2.zip.sha256`, attached to the [GitHub release](https://github.com/ValentinTorassa/blackice/releases/tag/v0.3.2). On 3 November 2026 the Homebrew section ran from the published 0.1.0 release, as an upgrade over a build installed by hand ([P5-02](https://github.com/ValentinTorassa/blackice/blob/main/evidence/P5-02-homebrew-upgrade-from-release-macos.md)), and the install script checked the release and installed it into a temporary folder instead of `/Applications` ([P5-03](https://github.com/ValentinTorassa/blackice/blob/main/evidence/P5-03-curl-install-script-sandbox-macos.md)). With 0.2.1, the uninstall steps and the script installing into `/Applications` ran from the published release ([P5-04](https://github.com/ValentinTorassa/blackice/blob/main/evidence/P5-04-install-start-faults-from-release-macos.md)). With a 0.3.0 candidate, the same steps, the first `start` with its lists and fx set up by `start` ran from no configuration and no fx ([P5-06](https://github.com/ValentinTorassa/blackice/blob/main/evidence/P5-06-onboarding-from-zero-macos.md)).

You need a Mac with Apple silicon (the build is arm64 only), macOS 14 or later, and an admin account. blackice has run on macOS 27.0.1 only.

## With the install script

```console
$ curl -fsSL https://blackice-macos.vercel.app/install.sh | sh
```

The script ([`site/lib/install.sh`](https://github.com/ValentinTorassa/blackice/blob/main/site/lib/install.sh)) downloads the zip and its checksum from the GitHub release and runs the checks of step 1, except `stapler validate`, which needs Xcode's command line tools (`spctl` checks the notarization as well). If a check fails, it stops before touching `/Applications`. Otherwise it copies `Blackice.app` to `/Applications` and writes `~/.local/bin/blackice`, a small script that runs `/Applications/Blackice.app/Contents/MacOS/blackice` (set `BLACKICE_BIN_DIR` for another folder). It starts nothing. Run it as your user, without `sudo`.

It stops if blackice is installed with Homebrew, and if another version is in `/Applications`. To replace that one, run it with `--force` (`curl -fsSL https://blackice-macos.vercel.app/install.sh | sh -s -- --force`), then see **To upgrade** under Rollback. Then continue with step 3.

## With Homebrew

```console
$ brew trust --cask valentintorassa/tap/blackice
$ brew install --cask valentintorassa/tap/blackice
```

The first command tells Homebrew to trust this cask: Homebrew loads casks from taps other than its own only after `brew trust`. The cask downloads the same zip from the GitHub release, checks it against the SHA-256 written in the cask, puts `Blackice.app` in `/Applications` and adds a `blackice` command to Homebrew's `bin` folder: a small script that runs `/Applications/Blackice.app/Contents/MacOS/blackice`, since a symbolic link does not work (see step 2). Homebrew does not run the signature checks of step 1; to run them, use the commands there on `/Applications/Blackice.app`. Then continue with step 3.

## 1. Download and check

Download both files into the same folder, then, in Terminal, in that folder:

```console
$ shasum -a 256 -c Blackice-0.3.2.zip.sha256
Blackice-0.3.2.zip: OK
$ ditto -x -k Blackice-0.3.2.zip .
$ codesign --verify --strict --deep --verbose=2 Blackice.app
$ codesign -dvv Blackice.app 2>&1 | grep -E '^(Identifier|TeamIdentifier)='
Identifier=com.valentorassa.blackice
TeamIdentifier=M294LK997M
$ xcrun stapler validate Blackice.app
$ spctl --assess --type execute -vv Blackice.app
```

`codesign --verify` should say `valid on disk` and `satisfies its Designated Requirement`, `stapler validate` should say the validate action worked, and `spctl` should say `accepted` with `source=Notarized Developer ID`. If any of them fails, or the Team ID is not M294LK997M, stop: do not install that copy.

Double-clicking the zip in Finder unpacks it as well. `ditto` is the command-line way that keeps the signature intact.

## 2. Move it to /Applications

```console
$ ditto Blackice.app /Applications/Blackice.app
```

Or drag it there in Finder. macOS activates system extensions only from an app in `/Applications`. To replace an installed copy, Terminal needs App Management (System Settings → Privacy & Security → App Management).

The `blackice` command is the app's own executable. Call it by its full path, or put its folder on your `PATH`, for example in `~/.zshrc`:

```sh
export PATH="/Applications/Blackice.app/Contents/MacOS:$PATH"
```

Use the folder on the `PATH`, or a script that runs the full path, rather than a symbolic link. The command checks that it runs as the signed app, and started through a link it does not: `blackice status` run through a symbolic link said it needs Blackice.app signed with the Developer ID and exited with status 69, while the full path, and a script that runs the full path, worked.

## 3. Write blackice.toml

`blackice start` reads `~/.config/blackice/blackice.toml` unless you pass `--config PATH`. If the file is not there, `start` asks a few questions and writes it. You pick the answers from lists with the arrow keys:

- the mode;
- in ask mode, who answers: fx, or you;
- apps to trust, from the apps and system extensions running now (a VPN client's network extension, such as Tailscale's, is one). Each may reach any host, and "Another app" takes a path such as `/Applications/Slack.app` or a signing identifier.

If you pick fx, `start` also sets fx up, as `blackice agent connect fx` does (see "Let an agent answer"). It stays in accept-all until fx is installed, signed in and tested, and loads ask mode at the end, so nothing waits on an answer before fx can give it. `blackice init` asks the same questions without starting anything. Or write the file yourself, starting in accept-all, which lets everything through and only logs:

```toml
mode = "accept-all"     # "accept-all", "ask" or "block-all"
timeout_seconds = 60    # in ask mode, no answer in time means deny

# Permanent rules: one app, by signing identifier (and Team ID unless it is Apple's), and its hosts.
[[allow]]
app = "com.apple.curl"
hosts = ["pypi.org"]
```

```console
$ mkdir -p ~/.config/blackice
$ blackice validate ~/.config/blackice/blackice.toml
```

For ask mode, add a `[[hook]]` that asks an agent and a rule that lets the agent reach its model provider, bound to its signature; the repository's [fx integration](https://github.com/ValentinTorassa/blackice/blob/main/integrations/fx/README.md) has the one for fx. [Configuration](/docs/configuration) covers every key. Before turning ask mode on, read the open problems in the [plan](https://github.com/ValentinTorassa/blackice/blob/main/docs/plan.md): a service missing from the built-in list of macOS services waits and is dropped, and Tailscale's DNS stops name lookups in ask and block-all unless a rule allows Tailscale's extension.

## 4. Start the filter

```console
$ blackice start
$ blackice status
```

`start` asks for Touch ID (or your login password), activates the network extension and saves the configuration. The first time, and after any deactivation, macOS holds the extension until you allow it. `start` opens System Settings where macOS asks, and prints the steps for your macOS:

- macOS 26 and later: General → Login Items. Scroll to Blackice, click ⓘ next to it, turn on Network Extension and click Done.
- macOS 15: General → Login Items & Extensions. Under Extensions, click ⓘ next to Network Extensions, turn on Blackice and click Done.
- macOS 14: Privacy & Security. Under Security, click Allow where it says Blackice was blocked from loading.

Then macOS asks whether "Blackice" may filter network content: click Allow. `start` waits up to 10 minutes for all this. The macOS 27 steps are from 27.0.1; the others follow Apple's layout of those versions. `blackice status` then says which mode blackice is in, whether the daemon runs your hooks, and how many connections are waiting.

## 5. Start the daemon

The daemon runs the hooks for connections that wait in ask mode. It runs as a LaunchAgent for your user and takes its hooks from the configuration that `start` saved:

```console
$ blackice agent install
```

`blackice agent uninstall` removes it. Without a daemon, ask mode still pauses connections, and they are dropped when their timeout passes.

### Let an agent answer

`blackice agent connect fx` sets fx up to answer the connections that wait in ask mode:

1. It finds fx and reads its signature. If fx is not installed, it shows fx's installer (`curl -fsSL https://fx.sh/setup.sh | bash`) and runs it if you say yes.
2. It gives fx a home of its own, `~/.config/blackice/agent`, with the blackice skill from Blackice.app. If fx has no sign-in there, it runs `fx login vercel`: press Enter to open the page fx names, and allow access. If the sign-in fails, it offers it again. It sets fx's rules there so that fx can run `blackice approve` and `blackice deny` and nothing else.
3. It runs the hook once on a sample connection, with `blackice` replaced by a stand-in so nothing is let through, and checks that fx answered with the event's token. AI Gateway needs a card on file for the Vercel team fx signed in with; without one, the test fails with HTTP 403 `customer_verification_required`.
4. Only then does it add to `blackice.toml` a rule that lets fx reach its model (Vercel's AI Gateway) in every mode, and the hook, and raise `timeout_seconds` to at least 60.
5. Unless the file is in ask mode already, it asks whether to switch. It loads the file (Touch ID) and starts the daemon.

In ask or block-all it switches to accept-all while fx is set up (Touch ID), since fx's own connections would wait until its rule is loaded, and the last step loads your file again. It knows fx only, so far. [integrations/fx/README.md](https://github.com/ValentinTorassa/blackice/blob/main/integrations/fx/README.md) has the same steps by hand.

## 6. Use it

- `blackice mode ask`, `blackice mode block-all`, `blackice mode accept-all`: change the mode (Touch ID each time).
- `blackice pending`: the connections waiting for an answer, and the current approvals.
- `blackice approve --app ID --host HOST --for 1h` and `blackice deny …`: answer as a person (Touch ID).
- The daemon's event log is `~/Library/Logs/blackice/events.jsonl`. The filter logs one line per decision to unified logging, where the app and host of each line show as `<private>` and the verdict and reason are public:

```console
$ /usr/bin/log show --last 10m --style compact --predicate 'subsystem == "com.valentorassa.blackice.filter"'
```

After changing `blackice.toml`, run `blackice start` again to load it (Touch ID).

## Uninstall

```console
$ blackice agent uninstall
$ blackice stop
$ rm -rf /Applications/Blackice.app
```

If you used the install script, also remove `~/.local/bin/blackice`. With Homebrew, run the first two commands, then `brew uninstall --cask blackice` instead of `rm`. Homebrew cannot deactivate the extension, so run `blackice stop` first. `brew uninstall --zap --cask blackice` also removes `~/Library/Logs/blackice`, but not your settings in `~/.config/blackice`.

`stop` asks for Touch ID, removes blackice's filter configuration and deactivates the extension. It needs no network. Moving the app to the Trash in Finder works as well as `rm`; either needs App Management for Terminal. `systemextensionsctl list` may show the extension as waiting to uninstall until the next restart. To also remove your settings and logs: `rm -rf ~/.config/blackice ~/Library/Logs/blackice`.

## Rollback

**If the network misbehaves** in ask or block-all, switch back first, then look:

```console
$ blackice mode accept-all
```

In accept-all the filter lets every connection through. A restart alone does not turn the filter off: macOS keeps a saved content filter across restarts.

**If `blackice` itself fails**, run it by its full path to see its message (`/Applications/Blackice.app/Contents/MacOS/blackice stop`). If `stop` still fails:

1. System Settings → Network → Filters (near VPN): remove blackice's content filter.
2. System Settings → General → Login Items: click ⓘ next to Blackice and turn off Network Extension (on macOS 15, Login Items & Extensions → Network Extensions).
3. `launchctl bootout gui/$(id -u)/com.valentorassa.blackice.daemon`, if the daemon is still loaded.
4. Move `/Applications/Blackice.app` to the Trash and restart. Then `systemextensionsctl list` should no longer show `com.valentorassa.blackice.filter` as `activated enabled`.

These labels are from macOS 27.0.1 and from memory.

**To go back to an earlier version**: macOS replaces an installed extension only with the same or a higher `CFBundleVersion`, so an older package does not install over a newer one. Uninstall (above), restart if `systemextensionsctl list` shows the extension waiting to uninstall, then install the older package from step 1 and allow the extension again in System Settings.

**To upgrade**, check the new package as in step 1, put its `Blackice.app` in `/Applications` over the old one (with Homebrew, `brew upgrade --cask blackice`; with the install script, run it with `--force`) and run `blackice start`: macOS replaces the running extension with the one with the higher build number. Then restart the Mac. On macOS 27.0.1, an extension upgraded this way kept filtering but had no XPC service until the Mac restarted, so the daemon, `pending`, `approve` and `deny` could not reach it and ask mode dropped everything it paused. `blackice start` checks for this after an upgrade, says so and exits with status 75. After the restart, run `blackice agent uninstall` and `blackice agent install`, so that the daemon runs the new binary.
