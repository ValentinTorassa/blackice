# CLI

The commands.

<Status />

| Command | What it does |
| --- | --- |
| `blackice init [--config PATH]` | Ask a few questions and write `blackice.toml`: the mode, how long ask mode waits, and apps to allow, by path or signing identifier. It never replaces a file that is there. |
| `blackice start [--config PATH]` / `blackice stop` | Activate the extension and start filtering with `blackice.toml` (asking `init`'s questions first when the file is missing), or stop filtering and deactivate it. The first `start` opens System Settings where you allow the extension. |
| `blackice status` | Whether blackice is on, its mode and what it does, the rules and hooks, whether the daemon is running, and how many connections wait. |
| `blackice mode accept-all \| ask \| block-all` | Change the mode. Connections that wait go on when the new mode allows them outright, as accept-all does, and are dropped otherwise. |
| `blackice pending` | Connections waiting for an answer, the approvals, and the denials of the last 10 minutes. |
| `blackice approve (--app ID [--team TEAM] \| --cdhash HEX) --host HOST [--for 1h]` | Allow one app to reach one host, or one address, until the approval expires. |
| `blackice deny (--app ID [--team TEAM] \| --cdhash HEX) --host HOST` | Drop the waiting connections and remove the approval. For 10 minutes the app's new connections to that host are dropped without asking, unless `approve` replaces the denial. |
| `blackice report [--last 1h]` | The filter's log over the last minutes or hours (`30m`, `2h`, at most `168h`), summed up: drops by reason and app, connections paused to ask by app, and in accept-all what ask mode would have done. No Touch ID. |
| `blackice daemon` | Run the hooks for paused connections and pass on their answers. The LaunchAgent runs it. |
| `blackice agent install` / `blackice agent uninstall` | Load the daemon's LaunchAgent for the current user, or unload and remove it. |
| `blackice agent connect fx [--config PATH]` | Set fx up to answer what waits in ask mode: its own home with the blackice skill and rules, one test on a sample connection, then its rule and hook in `blackice.toml`, ask mode if you say so, and the daemon. Touch ID once, to load it. |
| `blackice agent connect claude-code [--config PATH]` | The same for Claude Code: its own configuration directory and sign-in, with reading the event as its only tool. |
| `blackice menu [--login on \| off]` | Show blackice in the menu bar until you quit it. `--login on` opens it now and at each login, `--login off` stops that. |
| `blackice validate PATH` | Check a `blackice.toml` without loading it. |
| `blackice version` | The installed version and build. |

`start`, `stop`, `mode`, `approve` and `deny` ask for Touch ID, or your login password. Exit statuses follow sysexits: 0 done, 64 a usage error, 65 an invalid `blackice.toml`, 66 no file to read, 69 not running from the signed Blackice.app, or the filter did not answer, 70 a macOS request failed, or the filter kept another configuration than the one just saved, 73 `init` found a file already there, 75 run it again (after restarting the Mac, when blackice says so), 77 Touch ID cancelled, 130 the agent setup stopped by Control-C.

`approve` and `deny` are for a person, after Touch ID. Since 0.4.0 they take no `--token`: a hook answers by printing `deny` or `approve 10m` as its last line, and the daemon passes that on with the event's token, which never leaves the daemon and the extension (see [how a hook answers](/docs/configuration#how-a-hook-answers)). `--for` takes seconds, minutes or hours (`30s`, `10m`, `1h`), at most 24 hours. Without `--team`, `--app` names Apple's own code, which is signed without a Team ID. `--cdhash` names ad hoc signed code, which has no signing identity, by the CDHash that `codesign -dvvv` prints; a rebuild changes it and asks again.

`--host` takes a host name, or an IP address for a [connection with no name](/docs/configuration#connections-with-no-name), which `pending` shows as the address with "(no host name)": `blackice approve --app com.apple.ssh --host 100.66.32.75 --for 1h`. IPv4 is four numbers with no leading zeros, IPv6 may be written in any standard form, and a link-local address needs its interface, as in `fe80::1%en0`. An approval of an address covers only connections to that address that have no name. Wildcards and ranges are not accepted; a range goes in an `[[allow]]` rule.

`blackice report` reads the filter's lines in unified logging with `log show`. A line names its app in the clear and keeps its host private, so the report counts by reason and app, never by host. In accept-all every connection still goes through at once, and its line also says what ask mode would have decided with the same rules (`would=…`): a rule's line, `apple_service`, `loopback`, `ask`, `read_server_name` (the TLS hello would be read first, as for `curl` on port 443), or `drop:` and the reason. Accept-all looks nothing up and reads no DNS answers, so every address is taken to match its host, a connection with no host name from the system is judged by its address, and approvals do not count. After a day in accept-all, the apps under "asked about" are the ones to give rules before `blackice mode ask`.

`blackice menu` is the same app that opens when you open Blackice.app from Finder or Spotlight, or at login. Its icon is the blackice mark, full in ask and block-all and dimmed when blackice is off, in accept-all or not reachable, with the number of waiting connections next to it. Its menu shows the mode the filter decides in, each waiting connection with Allow for 10 Minutes, Allow for 1 Hour and Deny, the last verdicts from the event log with whether a hook or a person answered, a Mode submenu, and whether the daemon runs your hooks. Answers and mode changes are the same as `approve`, `deny` and `mode`, Touch ID included. Quitting it leaves the filter running. `blackice` with no arguments in a terminal still prints the usage: the menu starts only when LaunchServices opens the app (no arguments, launchd as its parent, no terminal). Open at Login uses `SMAppService` and works only for the signed Blackice.app in `/Applications`, where System Settings › General › Login Items lists it as Blackice. One copy runs at a time; another `blackice menu` says so and exits.

`blackice daemon` takes no options and reads no file. It gets its hooks and `timeout_seconds` from the extension, which holds the configuration that `blackice start` and `blackice mode` saved after Touch ID, so another copy of the daemon started by some other program still runs your hooks and no others. `agent install` must run from inside Blackice.app, because the LaunchAgent names that binary. It writes `~/Library/LaunchAgents/com.valentorassa.blackice.daemon.plist`, creates `~/Library/Logs/blackice` for the daemon's output and the event log, and loads the agent with `launchctl`. Neither `agent install` nor `agent uninstall` asks for Touch ID.
